# Configuration reference

Every configuration file and knob for the **Audio Flow Console** — the system that
plays a Spotify playlist on this PC and streams it as MP3 over the LAN to the
BrightSign sign (and optionally Sonos). This page is the reference for *what each
setting means*; for the moving parts and data flow see
[ARCHITECTURE.md](ARCHITECTURE.md), for day-to-day tasks see
[OPERATIONS.md](OPERATIONS.md), for the login/token mechanics see
[AUTHENTICATION.md](AUTHENTICATION.md), and for loudness leveling see
[AUDIO.md](AUDIO.md).

**Never print or paste secret values.** The Icecast passwords and the Spotify
tokens live in the files below. When you need to change one, edit the file in
place — do not copy its contents into chat, tickets, or screenshots.

## `stream.env` — Icecast connection & encoder

**Location:** `/home/jellyfin/.config/spotify-signage/stream.env`
**Permissions:** `600` (owner-only — it holds two passwords)
**Read by:** `stream.sh` (sourced on every pipeline start) **and** `server.js`
(read once at dashboard startup).

This file is `KEY=value` shell-syntax, auto-generated by the original
`spotify-signage-setup.sh`. `stream.sh` sources it to build the Icecast source
URL that ffmpeg pushes to; `server.js` parses the same file to know which
Icecast port, mount, and admin password to query for status and listener counts.

| Key | Meaning | Default |
|---|---|---|
| `ICECAST_SOURCE_PW` | Password ffmpeg uses to connect as the Icecast **source** client. Must match the `<source-password>` in `/etc/icecast2/icecast.xml`. **Secret.** | *(set at install)* |
| `ICECAST_ADMIN_PW` | Password the dashboard uses for the Icecast **admin** API (`/admin/listclients`) to list connected outputs. Must match `<admin-password>` in `icecast.xml`. **Secret.** | *(set at install)* |
| `ICECAST_HOST` | Host ffmpeg targets when pushing the source. | `localhost` |
| `ICECAST_PORT` | Icecast port for the source push and (in the dashboard) for status/admin queries. | `8000` |
| `ICECAST_MOUNT` | Mount path for the MP3 stream. The public listen URL is `http://172.16.50.100:<port><mount>`. | `/spotify.mp3` |
| `STREAM_BITRATE` | **Optional.** MP3 encoder bitrate in kbps (ffmpeg `-b:a`). Add this line to override. If absent, both `stream.sh` and the dashboard fall back to 128. | `128` |

Notes:
- `STREAM_BITRATE` is not written by the installer; the file typically has only
  the five keys above. Add `STREAM_BITRATE=192` (for example) to raise quality.
- The dashboard captures `ICECAST_PORT`, `ICECAST_ADMIN_PW`, `ICECAST_MOUNT`,
  and `STREAM_BITRATE` **once at startup**. Changing any of these therefore
  requires restarting **both** services (see
  [What requires a restart](#what-requires-a-restart)).
- The passwords here are the Icecast side. If you change them you must also edit
  `/etc/icecast2/icecast.xml` to match, then restart `icecast2` and
  `spotify-stream.service`.

## `audio.env` — loudness normalization

**Location:** `/home/jellyfin/.config/spotify-signage/audio.env`
**Permissions:** `600` (rewritten by the dashboard at this mode)
**Read by:** `stream.sh` (sourced on pipeline start; `2>/dev/null || true`, so a
missing file is harmless) and `server.js` (`GET/POST /api/audio`).

This controls librespot's **volume normalization** (loudness leveling between
tracks). It is normally managed from the dashboard's **Live Output Level** card,
which writes this file and restarts the pipeline for you. You can also edit it by
hand. Full background is in [AUDIO.md](AUDIO.md).

`stream.sh` only adds the librespot normalization flags when `NORMALIZE=1`;
otherwise none of the other keys have any effect. **Gapless is always on** and is
not configurable here (the pipeline never passes `--disable-gapless`). librespot
has no crossfade — smooth song transitions come from gapless + normalization, not
crossfade.

| Key | Meaning | Allowed values | Default |
|---|---|---|---|
| `NORMALIZE` | Master on/off for volume normalization. Off → the other keys are ignored. | `1` / `0` | `1` (dashboard default is on; if the file is absent, `stream.sh` treats it as `0`) |
| `NORMALIZE_GAIN_TYPE` | librespot `--normalisation-gain-type`: which loudness reference to use. | `track` \| `album` \| `auto` | `track` |
| `NORMALIZE_METHOD` | librespot `--normalisation-method`. | `basic` \| `dynamic` | `dynamic` |
| `NORMALIZE_PREGAIN` | librespot `--normalisation-pregain` in dB — the "Level" slider. Clamped by the dashboard to the range below. | `-10`..`10` (dB) | `0` |

When `NORMALIZE=1`, `stream.sh` appends:

```
--enable-volume-normalisation \
--normalisation-gain-type <NORMALIZE_GAIN_TYPE> \
--normalisation-method   <NORMALIZE_METHOD> \
--normalisation-pregain  <NORMALIZE_PREGAIN>
```

**Applying changes:** the dashboard's `POST /api/audio` writes this file and then
**restarts `spotify-stream.service`** automatically (a few seconds of re-buffer;
the scheduler then resumes playback and the BrightSign reconnects on its own). If
you edit `audio.env` by hand, you must restart the pipeline yourself:

```bash
systemctl --user restart spotify-stream.service
```

## `schedules.json` — weekly timeline

**Location:** `/home/jellyfin/.config/spotify-signage/schedules.json`
**Permissions:** `600` (written by the dashboard with mode `600`, 2-space JSON)
**Read by:** `server.js` — the reconciler reloads it every ~15s and on every
`/api/schedules` request; **no restart needed** for edits to take effect.

This is the drag-to-paint weekly calendar. It is normally edited only through the
dashboard (`PUT /api/schedules` replaces the whole timeline). Hand-editing is
possible but the server re-sanitizes everything it reads.

### Top-level shape

```json
{
  "version": 2,
  "enabled": true,
  "blocks": [ { "id": "...", "day": 0, "start": 435, "end": 780,
               "playlist": "3Z5zejprig1SlzGBXaSmma",
               "name": "…", "shuffle": false } ]
}
```

| Field | Meaning | Default |
|---|---|---|
| `version` | Store format version. Current format is `2`. An old array-style file is auto-migrated to an empty v2 timeline. | `2` |
| `enabled` | Automation master switch. `false` = hands-off (the reconciler never touches playback). | `true` |
| `blocks` | Array of scheduled blocks (below). An **empty** array is also fully hands-off, so a blank grid never mutes manual playback. | `[]` |

### Block fields

| Field | Meaning | Constraints (enforced on save) |
|---|---|---|
| `id` | Stable block id. | Auto-generated if missing. |
| `day` | Day of week. **0 = Sunday … 6 = Saturday.** | Clamped to `0..6`. |
| `start` | Start time, **minutes from midnight**. | `0..1440`, rounded to nearest 5. |
| `end` | End time, minutes from midnight. | `0..1440`, rounded to nearest 5, and must be `> start`. |
| `playlist` | Spotify playlist **id** (the `3Z5z…` part, not a full URL). | Normalized from any URL/URI form; block dropped if it can't resolve. |
| `name` | Display label for the block. | Trimmed to 80 characters. |
| `shuffle` | Shuffle this block's playlist. | Coerced to boolean. |

Semantics (the timeline is **authoritative**):
- Whichever block covers *now* (this weekday + minute-of-day) is the playlist
  that should be playing; if two overlap, the earlier `start` wins (the UI
  prevents overlaps anyway).
- Any moment **not** covered by a block = paused/silent — **except** when
  automation is off or the timeline is empty, which is fully hands-off.
- Blocks **cannot cross midnight**; use one block per day. Times snap to 15 min
  in the UI (the server rounds to 5).
- The reconciler is level-based: it only issues a command on real drift and never
  restarts a correct playlist. A dashboard Play/Pause arms a 4-hour manual
  override. Details in [ARCHITECTURE.md](ARCHITECTURE.md) and
  [DASHBOARD.md](DASHBOARD.md).

## `token.json` — Spotify OAuth tokens

**Location:** `/home/jellyfin/.config/spotify-signage/token.json`
**Permissions:** `600` (owner-only — it holds live credentials)
**Written by:** `spotify_oauth.py` (at first login) and `server.js` (on each
refresh, rewritten at mode `600`).
**Read by:** `server.js` on demand; **no restart needed** — the dashboard reads
the file fresh each time.

Single JSON object. **Never print its contents.** The dashboard keeps an
in-memory access-token cache and only refreshes when the access token is <60s
from expiry (~once/hour), using the `refresh_token`.

| Field | Meaning |
|---|---|
| `access_token` | Short-lived bearer token for the Spotify Web API. **Secret.** |
| `refresh_token` | Long-lived token used to mint new access tokens. **Secret — this is the one that matters.** |
| `scope` | Space-separated granted scopes (see below). |
| `expires_at` | ISO timestamp when the current access token expires. |
| `expires_in` | Access-token lifetime in seconds (typically 3600). |
| `token_type` | Always `Bearer`. |

Scopes this system uses (granted at login by `spotify_oauth.py`):
`user-read-playback-state`, `user-modify-playback-state`,
`user-read-currently-playing`, `playlist-read-private`,
`playlist-read-collaborative` (and `user-read-private` where granted, for the
product-tier/display-name read).

Recovery: if this file is deleted or the refresh token is revoked, the dashboard
shows the amber **Connect Spotify** banner. Re-link with `POST /api/auth/start`
(the banner/avatar) or run `spotify_oauth.py auth` directly. See
[AUTHENTICATION.md](AUTHENTICATION.md).

## `cert.pem` / `key.pem` — OAuth callback TLS

**Location:** `/home/jellyfin/.config/spotify-signage/cert.pem` and `key.pem`
**Permissions:** `cert.pem` `664` (public certificate), `key.pem` `600`
(private key — owner-only)
**Used by:** `spotify_oauth.py`, only while a login is in progress, to run the
HTTPS callback server on port **8989**.

Spotify's 2025 "secure redirect" policy rejects `http` loopback for non-127.0.0.1
hosts, rejects `localhost`, and requires an exact redirect match — so the
registered redirect URI is `https://172.16.50.100:8989/login`, which needs a
real TLS listener. These files are the self-signed cert/key for that listener.

Current certificate:

| Property | Value |
|---|---|
| Subject / Issuer | `CN=172.16.50.100` (self-signed) |
| Subject Alt Names | IP `172.16.50.100`, IP `127.0.0.1`, DNS `localhost` |
| Valid | 2026-07-03 → 2028-10-05 |

If the cert expires or the host IP changes, regenerate a self-signed pair
covering the new IP and drop them in with the same filenames (keep `key.pem` at
`600`). The browser will warn about the self-signed cert during login — that is
expected; proceed past it. More in [AUTHENTICATION.md](AUTHENTICATION.md).

## `server.js` environment-variable overrides

`server.js` reads these environment variables at startup (each has a built-in
default, so none are strictly required). The `signage-dashboard.service` unit
sets `PORT` and `HOST_IP`; the rest are only needed if you ever change the
Spotify app or the device name.

| Variable | Controls | Default |
|---|---|---|
| `PORT` | TCP port the dashboard listens on (binds `0.0.0.0`). | `8088` |
| `HOST_IP` | LAN IP used to build the public stream URL and the default redirect URI. | `172.16.50.100` |
| `SIGNAGE_CLIENT_ID` | Spotify app (PKCE) client id used for auth/refresh. | `99aa015e38634f389d6b8d1e16b3a578` (app "Signage Player") |
| `SIGNAGE_REDIRECT` | OAuth redirect URI passed to `spotify_oauth.py auth`. Must exactly match a URI registered on the Spotify app. | `https://<HOST_IP>:8989/login` |
| `SIGNAGE_DEVICE` | librespot Connect device name the dashboard targets for playback. Must match the `--name` in `stream.sh` (`Signage`). | `Signage` |

To change one persistently, add an `Environment=` line to
`signage-dashboard.service` (see below), then `daemon-reload` and restart the
dashboard. Changing `SIGNAGE_DEVICE` also means changing `--name "Signage"` in
`stream.sh` (and restarting the pipeline) so the two agree.

## systemd `--user` units

Both application services are systemd **user** units for the `jellyfin` user.
User lingering is enabled, so they run without an interactive login and start at
boot.

**Location:** `/home/jellyfin/.config/systemd/user/`
Enabled via symlinks in `…/default.target.wants/`.

### `spotify-stream.service` — the audio pipeline

```ini
[Unit]
Description=Spotify (librespot pipe) -> ffmpeg MP3 -> Icecast for BrightSign
After=network-online.target

[Service]
Type=simple
ExecStart=/home/jellyfin/.config/spotify-signage/stream.sh
Restart=always
RestartSec=3

[Install]
WantedBy=default.target
```

Runs `stream.sh`, which sources `stream.env` + `audio.env` and launches the
librespot → `relay.py` → ffmpeg → Icecast chain. Auto-restarts on exit.

### `signage-dashboard.service` — the web dashboard

```ini
[Unit]
Description=Signage Audio Flow dashboard (Material Expressive)
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/home/jellyfin/signage-dashboard
ExecStart=/home/jellyfin/.local/bin/node /home/jellyfin/signage-dashboard/server.js
Environment=PORT=8088
Environment=HOST_IP=172.16.50.100
Restart=always
RestartSec=3

[Install]
WantedBy=default.target
```

Runs `server.js` on `0.0.0.0:8088`. Note the Node binary is the user-local
`/home/jellyfin/.local/bin/node` (v24), not `/usr/bin/node`. The two
`Environment=` lines are where you'd set the [server.js
overrides](#serverjs-environment-variable-overrides).

### Related services

| Service | Type | State | Notes |
|---|---|---|---|
| `spotify-stream.service` | `--user` | enabled | Audio pipeline. |
| `signage-dashboard.service` | `--user` | enabled | Web dashboard. |
| `icecast2` | **system** | enabled/active | The MP3 broker. Managed with `sudo systemctl … icecast2`; config at `/etc/icecast2/icecast.xml`. |
| `spotify-silence.service` | `--user` | **disabled / obsolete** | Superseded by `relay.py`. The unit file still exists but is not linked into `default.target.wants`. Do not enable it. |

### Managing the units

```bash
# user services (pipeline + dashboard)
systemctl --user restart spotify-stream.service
systemctl --user restart signage-dashboard.service
systemctl --user status  spotify-stream.service
journalctl --user -u spotify-stream -f
journalctl --user -u signage-dashboard -f

# after editing any unit file
systemctl --user daemon-reload

# Icecast is a SYSTEM unit
sudo systemctl restart icecast2
sudo journalctl -u icecast2
```

## What requires a restart

The pipeline reads its config only when it launches; the dashboard reads *most*
things live but caches a few at startup. Use this table when you change a file.

| You changed… | Restart… | Why |
|---|---|---|
| `audio.env` | `spotify-stream.service` | librespot picks up normalization flags only at launch. The dashboard's `POST /api/audio` does this restart for you; a hand edit does not. |
| `stream.sh` | `spotify-stream.service` | It *is* the pipeline command. |
| `stream.env` — `ICECAST_SOURCE_PW`, `ICECAST_HOST`, `ICECAST_PORT`, `ICECAST_MOUNT` | `spotify-stream.service` | ffmpeg builds the Icecast source URL from these at launch. |
| `stream.env` — `ICECAST_PORT`, `ICECAST_ADMIN_PW`, `ICECAST_MOUNT`, `STREAM_BITRATE` | **also** `signage-dashboard.service` | The dashboard caches these at startup for status/listener queries and the displayed bitrate. |
| `server.js` (or its `Environment=` values / unit file) | `signage-dashboard.service` (after `daemon-reload` if the unit changed) | The dashboard process must reload the code/env. |
| Any systemd unit file | `daemon-reload`, then restart that unit | systemd caches parsed unit files. |
| Icecast passwords in `stream.env` **and** `/etc/icecast2/icecast.xml` | `icecast2` (system) **and** `spotify-stream.service` | Both sides of the source/admin auth must match. |

No restart needed (read live):
- **`schedules.json`** — the reconciler reloads it every ~15s; dashboard edits
  apply on the next tick.
- **`token.json`** — read fresh on each use; refreshes itself in place.
